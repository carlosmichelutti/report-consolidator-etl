# Report Consolidator ETL

A Python ETL pipeline that consolidates customer reports in XLSX format,
normalizes their data, and persists the result to an Excel file and PostgreSQL.

## How the pipeline works

The pipeline is divided into three stages:

1. **Extract:** reads every `.xlsx` file available in `data/input`.
2. **Transform:** validates required columns, normalizes text, CPF numbers, and
   dates, removes additional columns, and consolidates the reports into a
   single DataFrame.
3. **Load:** exports the result to
   `data/output/consolidated_clients.xlsx` and replaces the `clientes` table in
   PostgreSQL.

## Prerequisites

Install the following tools before running the project locally:

- [Python 3.13 or later](https://www.python.org/)
- [uv](https://docs.astral.sh/uv/)
- [Docker](https://www.docker.com/) with Docker Compose

## Environment setup

Clone the repository and enter the project directory:

```bash
git clone <repository-url>
cd report-consolidator-etl
```

Create a local environment file from the provided example:

```bash
cp .env.example .env
```

On PowerShell, use:

```powershell
Copy-Item .env.example .env
```

The `.env.example` file contains the required database settings:

```dotenv
DATABASE_HOST=localhost
DATABASE_PORT=5432
DATABASE_NAME=postgres
DATABASE_USER=postgres
DATABASE_PASSWORD=postgres1234
```

Change these values in `.env` if you want to use different credentials or a
different local port.

## Installing dependencies

Synchronize the virtual environment and install the runtime and development
dependencies recorded in `uv.lock`:

```bash
uv sync
```

uv automatically creates and manages the virtual environment in `.venv`.

## Starting PostgreSQL

Create and start the PostgreSQL service in the background:

```bash
docker compose up -d postgres
```

Verify that the container is running and healthy:

```bash
docker compose ps
```

Docker Compose uses PostgreSQL 16, applies the settings from `.env`, and stores
the database data in the named `postgres_data` volume.

## Preparing input files

Add the `.xlsx` reports to the `data/input` directory. Each report must contain
the following columns:

| Column | Description |
| --- | --- |
| `id_cliente` | Customer identifier |
| `nome_cliente` | Customer name |
| `cpf` | Customer CPF number |
| `data_nascimento` | Date of birth |
| `data_registro` | Registration date |
| `email` | Email address |
| `status` | Registration status |

Dates may use the `YYYY-MM-DD`, `YYYY-MM-DD HH:MM:SS`, or
`YYYY-MM-DDTHH:MM:SS` format. Additional columns are removed during the
transformation stage.

## Running the pipeline

Once PostgreSQL is healthy and the reports are available in `data/input`, run:

```bash
uv run python -m scripts.pipeline
```

After a successful execution:

- the consolidated file will be available at
  `data/output/consolidated_clients.xlsx`;
- the `clientes` table will be created or replaced in PostgreSQL;
- logs from each pipeline stage will be displayed in the terminal.

The file and database table always represent the latest consolidation because
they are replaced on every execution.

## Running tests

Run the automated test suite with:

```bash
uv run pytest
```

The tests cover database configuration and access, extraction, transformation,
loading, and pipeline orchestration.

## Code quality

Analyze the project with Ruff:

```bash
uv run ruff check .
```

Apply safe automatic fixes with:

```bash
uv run ruff check . --fix
```

## Stopping the environment

Stop and remove the container without deleting the persisted database data:

```bash
docker compose down
```

To also remove the volume and delete the local PostgreSQL data, run:

```bash
docker compose down --volumes
```
